# „Пасището“ — план за имплементация

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Пълна продукционна версия на „Бикове и крави“ по дизайна „Пасището“: соло (дневно/свободно), дуел (надпревара/класически, бърз мач и покана), бот „Плашилото“, тефтерче, класация, профил; мобилен и десктоп изглед; BG + EN.

**Architecture:** pnpm monorepo. `packages/game-core` е чиста, изоморфна логика с 100% тестове; `apps/server` (Cloudflare Worker: Hono REST + Durable Objects за стаите + Drizzle към Supabase Postgres) е единственият, който знае тайното число; SPA-то се сервира от същия Worker като static assets; `apps/web` (Vite + React 19) е PWA, което само огледално показва сървърното състояние. Портове/адаптери: `AuthPort` (Supabase или фалшив за тестове), `Repo*` (Drizzle или в памет), така че цялото REST и стаите се тестват без база и без Supabase.

**Tech Stack:** pnpm 9, TypeScript 5.6, Vitest 2, Vite 6, React 19, React Router 7, Zustand 5, TanStack Query 5, react-i18next, vite-plugin-pwa, Hono 4 на Cloudflare Workers, Durable Objects (hibernation API, alarms), Wrangler 3, `@cloudflare/vitest-pool-workers`, Drizzle ORM + `postgres` (Hyperdrive), `jose`, `@supabase/supabase-js` 2, `glicko2`, `@noble/hashes`, Zod, Playwright, Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-20-pasishte-design.md` (чети и него: всяка стойност по-долу идва оттам или от прототипите в `design/pasishte/`).

## Global Constraints

- Тайното число и проверката на опит са само на сървъра; никой REST отговор или Colyseus state не съдържа `secret` преди края на играта (спец. §2 анти-цели, §6.2).
- В опашката за бърз мач има само хора; ботът е отделен режим (§5.3).
- Рейтингът се променя само при бърз мач (`opponent_kind = 'quick'`), показва се закръглен; няма класация по рейтинг (§5.2, §9 В5).
- Гост (анонимен Supabase потребител): соло + бот + покана от приятел; **не** бърз мач, **не** класация (§9 В3).
- N ∈ {3,4,5}; „С нулата“ изкл. → цифри 1–9; вкл. → 0–9 и 0 може отпред (§4). Няма друго правило за първата цифра.
- Формули (§4): `prog = 1 − ln(left)/ln(total)`; `fog = 0.9·(1−prog)`; `sunY = 176 − 150·prog`; `dawn = 0.75·(1−prog)`; `score = max(50, round((1200 − (attempts−1)·90 − secs·1.5)·k))`, k = 0.8/1/1.3; звезди ≤5→5, ≤20→4, ≤45→3, ≤75→2, иначе 1; ниво = 1 + ⌊XP/1500⌋; XP дуел 120/70/40; бот 40 XP само при победа на ниво 3/4.
- Отброяване 3-2-1 по 700 ms, игра започва на 2100 ms; часовникът тръгва от „Старт“ (§4).
- Денят се сменя в 00:00 Europe/Sofia; дневно число = `HMAC-SHA256(daily_salt, "YYYY-MM-DD|N|zero") mod total`; важи първата завършена дневна игра, повторните са „упражнение“ (§4).
- Класически дуел: 60 s на ход, предупреждение на 15 s, изтичане = загуба; надпревара: таван 15 min → реми без рейтинг; реконект 30 s (§5.2, §11).
- Код за покана: 5 символа от `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`, валиден 30 min или до старт (§5.2, §11).
- Сървърът връща кодове (`ERR_*`, `OUTCOME_*`), не текст; клиентът превежда (§6.5). Български е референтният текст; английският се пише в същата задача.
- Визия 1:1 с `design/pasishte/pasishte.css` и `.dc.html`: Nunito, същите цветове, keyframes, класове. Без Tailwind, без друг UI kit (§2 анти-цели).
- `prefers-reduced-motion`: без безкрайни анимации, мигновени преходи, конфети → статичен банер (§6.4).
- API отговор: `{ ok: true, data }` или `{ ok: false, error: { code } }` (глобално правило „API response format“).
- Файлове до 800 реда, функции до 50 реда; без мутация на входни обекти; Zod валидация на всеки вход на сървъра.
- Хостинг: един Cloudflare Worker (static assets + `/api` + `/ws`), Supabase безплатен план с дневен keep-alive cron; нулев фиксиран разход (§9).
- Без монетизация: никакви реклами, дарения, платени нива, `supporter` флагове (§9).
- Един клон `feat/pasishte`, чести комити (`<type>: <описание>` на български), един PR накрая (§7).

## Review Focus

Случаи, които спецификацията подсказва, но нито един екран не показва; всеки е закачен като тест към задачата, която държи кода:

1. **Опит с повтаряща се цифра или грешна дължина през REST/WS** (напр. `"1123"`, `"12"`, `"abcd"`) → `ERR_CODE` без промяна на състоянието (Задача 15, 24).
2. **Опит преди „Старт“ или след край на играта** → `ERR_NOT_STARTED` / `ERR_FINISHED`, таймерът не тръгва (Задача 14, 22).
3. **Втора дневна игра в същия ден** → създава се с `practice: true`, не променя класация, XP, серия (Задача 14, 16).
4. **Играч, прекъснал връзката в класически дуел по време на своя ход** → ходовият таймер продължава да тече, 30 s реконект не го спира; изтичане = загуба (Задача 22, 24).
5. **Гост се опитва да влезе в опашката или да види класацията** → `ERR_GUEST` (Задача 16, 25).
